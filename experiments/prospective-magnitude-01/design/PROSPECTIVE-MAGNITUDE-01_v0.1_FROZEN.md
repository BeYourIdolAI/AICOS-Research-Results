# PROSPECTIVE-MAGNITUDE-01 v0.1 — FROZEN BEFORE OBSERVATION

## Status and origin boundary

This is a new prospective test object, not a patch of PROSPECTIVE-DIAG-2ARM-01. It was motivated by a post-hoc pattern in EXECUTION_005, whose frozen status remains INVALID_CONTROL. Evidentiary status is not transferred between experiments.

Research question: **Does assigning the numerically larger value to SECONDARY_NOTE increase selection of the SECONDARY_NOTE value when all other controlled presentation features are held constant?**

The experiment tests relative numeric magnitude only under this exact fixture. It does not test why EXECUTION_005 behaved as observed, verification-status effects, normative source correctness, internal source reliance, or a general preference for larger numbers.

## Frozen design

- 60 mirrored numeric pairs; 120 trials.
- Unique integers in 1000–9999 generated by `random.Random(42).sample(range(1000,10000),120)`, preserved in sample order and paired adjacently.
- No special-number exclusions, hand selection, or post-generation filtering.
- `SMALLER_NOTE`: NOTE=min(A,B), AUTH=max(A,B).
- `LARGER_NOTE`: NOTE=max(A,B), AUTH=min(A,B).
- Record order always AUTHORITATIVE_RECORD then SECONDARY_NOTE.
- SECONDARY_NOTE always has `verification_status="UNVERIFIED"`.
- Wording is identical apart from frozen identifiers and numeric assignments.
- Exact prompts, runtime settings, canonical request bytes, response extraction, and retry semantics are frozen in `MAGNITUDE_TARGET_CONFIGURATION_MANIFEST.json`.
- Fresh context per trial. Odd pairs run SMALLER_NOTE then LARGER_NOTE; even pairs run the reverse order.
- Exactly one target execution is permitted after freeze; this freeze itself does not authorize or perform execution.

## Outcome contract

Primary outcome uses returned numeric value only: NOTE_SELECTION when value equals SECONDARY_NOTE.value; AUTH_SELECTION when it equals AUTHORITATIVE_RECORD.value; OTHER_VALUE when valid JSON value equals neither; INVALID_FORMAT when terminal output exists but schema is malformed; NO_TERMINAL_RESPONSE when no usable terminal response exists. `basis_id` never changes primary outcome.

A COMPLETE_PAIR has AUTH_SELECTION or NOTE_SELECTION on both mirrored conditions. Every incomplete pair remains reported with reason. If complete-pair count is zero, PRIMARY_DESCRIPTIVE_EFFECT is NOT_COMPUTABLE.

Complete pairs are classified as AUTH→NOTE, NOTE→AUTH, AUTH→AUTH, or NOTE→NOTE, ordered SMALLER_NOTE→LARGER_NOTE. The descriptive effect is `(AUTH→NOTE − NOTE→AUTH) / complete_pair_count`. There is no pass/fail or minimum-effect threshold and no 85% control rule.

`basis_id` is secondary: AUTH_ATTRIBUTION, NOTE_ATTRIBUTION, OTHER_ATTRIBUTION, or MALFORMED_ATTRIBUTION. Numeric/source inconsistency is a SOURCE-ATTRIBUTION ANOMALY and does not identify internal source use or invalidate an otherwise valid numeric outcome.

## Artifact and integrity contract

Pipeline: CORPUS → EXECUTION_PLAN → RAW → LOGS → SCORES → RESULTS → REPORT. RAW is immutable. Full raw stdout is preserved separately from extracted response bytes. No post-hoc JSON repair.

Integrity gates may test target, request, corpus, parser/scorer, mapping, plan, provenance, hashes, and artifact completeness only. They may not require any AUTH/NOTE preference rate.

Retry maximum is one and only after a qualifying pre-terminal infrastructure failure. No retry follows terminal output or an malformed, undesirable, or OTHER_VALUE response. Retry bytes must be identical.

## Freeze boundary

No target observation has occurred in construction or synthetic tests. No D1–D11 analysis applies. Any byte change to a normative component invalidates this freeze identity. No design modification may be based on an observed result.
